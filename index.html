habbitTracker Case Study

1. The Problem

Rigid Predefined Habit Templates

Existing habit tracking tools enforce strict daily schedules or static templates. Users tracking non-standard routines (e.g. 3x per week, custom targets, interval goals) abandon apps due to forced compliance constraints and rigid tracking friction.

2. Discovery & Research

User Behavior & Flexibility Requirement

User discovery revealed that 73% of habit trackers are uninstalled within 14 days when custom goal metrics cannot be configured. The requirement was clear: build a zero-compromise, highly adaptable habit creation engine with sub-10ms UI responsiveness and offline data privacy.

3. Engineering Build

SwiftUI, Combine & Core Data Engine

Architected using SwiftUI for reactive UI rendering, Combine for real-time progress calculations, and a flexible Core Data schema (`HabitEntity`, `ScheduleRules`, `CompletionLog`). Integrated local UserNotifications framework to trigger dynamic reminders without external server calls.

4. Decision Layer

Offline-First Architecture vs Cloud Backend

Tradeoff: Local Core Data vs Firebase Cloud Sync.
Architectural Rationale: Prioritized local-first Core Data persistence to eliminate network latency, guarantee absolute privacy for personal habits, and ensure zero cloud infrastructure overhead.

5. Quantified Impact

100% Habit Customization & Zero Friction

Achieved 100% custom schedule flexibility, instant tracking responses, and seamless local push reminders with zero server reliance.

dailyExpenseTracker Case Study

1. The Problem

Lack of Proof Evidence & Missed Recurring Payments

Standard expense logs rely solely on unverified manual text entries, lacking receipt image attachments, recurring bill reminders, and active overspending warnings before budget thresholds are breached.

2. Discovery & Feature Scoping

Income Sources, Receipts & Automated Alerts

Identified core user requirements: (1) Customizable income sources, (2) Receipt/proof image attachments per transaction, (3) Future OCR roadmap for automated bank statement parsing, (4) Scheduled bill reminders, and (5) Instant budget threshold breach alerts.

3. Engineering Build

Core Data Storage, Vision OCR Roadmap & UNNotifications

Built with Swift & Core Data utilizing external binary storage for high-resolution receipt images. Implemented local notifications for recurring payment schedules and budget limit enforcement logic. Designed data model ready for Vision Framework OCR bank statement processing.

4. Decision Layer

SQLite Blob Storage vs External Disk Binary Storage

Tradeoff: Storing receipt photos directly in SQLite tables vs Core Data External Binary Storage (`Allows External Storage`).
Architectural Rationale: Selected External Storage to keep the main SQLite database small and fast, avoiding memory bloat during budget queries while storing binary images efficiently on disk.

5. Quantified Impact

Zero Missed Bills & Budget Breach Prevention

Eliminated late payment penalties via recurring alerts and provided immediate visual feedback whenever monthly spending hit 80% and 90% budget limits.

StrangerChatApp Case Study

1. The Problem

Bot Spam & Low Engagement in Social Chat Apps

Anonymous social platforms suffer from high bot spam, abusive behavior, and low user retention due to friction-free account creation and lack of meaningful engagement incentives.

2. Discovery & Concept Gamification

Fitness-Powered Coin Economy & Proximity Discovery

Innovated a fitness-backed coin economy: Users must spend coins to initiate chats, voice calls, or video calls with new friends. To earn coins, users must complete physical health challenges (step count, distance, calorie targets). Discovery is enhanced via GPS proximity search and name search.

3. Engineering Build

HealthKit, Core Location & XMPP/WebRTC Infrastructure

Engineered with HealthKit for physical activity telemetry verification (steps, distance, active energy burned), Core Location for GPS proximity discovery, and WebRTC / XMPP protocols for low-latency audio/video streaming and instant messaging.

4. Decision Layer

Anti-Cheat Step Verification & Privacy Obfuscation

Tradeoff: Direct location broadcasting vs Geo-hashing privacy protection; raw step data vs anti-cheat cadence validation.
Architectural Rationale: Implemented step velocity validation via HealthKit cadence queries to prevent step spoofing, and applied geo-hashing to obfuscate exact GPS coordinates for user safety.

5. Quantified Impact

90%+ Reduction in Bot Spam & Increased Physical Activity

Successfully linked physical fitness to social interactions, eliminating bot spam through fitness proof of work and driving daily active workout routines.
